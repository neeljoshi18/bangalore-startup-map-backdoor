# Backdoor · Bengaluru hiring map

Every company hiring in Bengaluru, on one map, framed as a conversation with Backdoor.
The chat column is the UI: quick replies filter, answers come back as bubbles, companies
are link-preview cards with their live roles and a "Get me in" button that opens WhatsApp.

Live: https://neeljoshi18.github.io/bangalore-startup-map-backdoor/ (GitHub Pages, from `main`).
Porting notes for the Backdoor app are in `HANDOFF.md`.

## Files

- `artifact.html` – the page source (no doctype; the Claude artifact host wraps it).
- `index.html` – the deployable page, generated by `scripts/build-site.mjs` from `artifact.html` with the full
  document head: title, description, canonical, Open Graph / Twitter cards (`assets/og.jpg`), favicon. Set
  `SITE_URL` when building for another address: `SITE_URL=https://backdoorai.app/bengaluru/ node scripts/build-site.mjs`.
- `data/basemap-{region,city,core}.jpg` + `data/basemap.json` – the basemap, baked by `scripts/basemap.mjs` from
  OpenFreeMap's "liberty" style (OpenMapTiles + OpenStreetMap data; keep the attribution line). Three levels so the
  pitched intro, the city view and the belt (where the tour zooms to ~14) all stay sharp without a tile server.
- `data/startups.json` – what the map renders (logos embedded as data URIs). Built by `scripts/build-data.mjs`.
- `assets/ghost-256.png`, `assets/ghost-48.png` – the real Backdoor ghost (`public/images/logo-icon.png` in the app repo).
- `assets/logos/` – company logos fetched by the scraper.
- `raw/` – scraper output and the DB export; not needed at runtime.

## Data sources (merged by `scripts/build-data.mjs`, deduped by domain)

1. `raw/scrape.json` – `scripts/scrape.mjs` probes public job-board APIs (Greenhouse, Lever, Ashby,
   Workable, SmartRecruiters, Workday, Amazon, PhonePe's feed, Google's careers HTML) for ~200
   well-known companies and keeps roles whose location is Bengaluru. Brands whose careers sites have
   no public API (Flipkart, Myntra, Zomato, Blinkit, Zepto, Microsoft, Apple, Uber, Ola, Rapido,
   cult.fit, Practo, Juspay) are added from the `BRANDS` list with a careers link only; they carry
   `careersOnly: true` and no role count. `FAMOUS` marks recognisable names: they win cluster stacks
   and define the video frame. `scripts/geocode.mjs` places offices from OpenStreetMap office POIs.
   The map shows only recognisable names (`FAMOUS_ONLY`, default on) and only those with a proper logo.
   Logos: `scripts/logos.mjs --all` (site icons, then Google's favicon service), `scripts/logos-brands.mjs`
   (Google Play icons for consumer apps, Wikimedia logos for the big enterprises). `scripts/rec/sheet.mjs` renders a
   contact sheet to eyeball them.
2. Backdoor's research cache (DB export + fixture) is off by default. `USE_RESEARCH=1 node scripts/build-data.mjs`
   merges it back in once `raw/india.json` exists.

## Deploy

The site is static: `index.html`, `data/`, `assets/`. GitHub Pages serves it from `main` at the URL above
(`.nojekyll` keeps Pages from touching the files). Any static host works the same way; on Vercel, drop the
folder into `public/bengaluru/` of the app or deploy this repo as its own project.

Placement: companies matched to an OpenStreetMap office get exact coordinates and the nearest
neighbourhood label. Others fall back to a known area (`area` in the scraper's candidate list) or are
spread across the central startup belt and labelled plainly "Bengaluru".

## Keys (hidden, for recording)

- `R` replay the intro (chat types itself out while the city flies in and logos drop)
- `V` video frame: fits the map to the recognisable brands (the box is `videoFrame` in `data/startups.json`)
- `P` tour: fits the video frame, then visits recognisable companies about every 3 s (shuffled, no repeats, never two stops within 400 m); press again to stop
- `H` map only (hides the chat column and HUD)

Nothing on the page advertises these. The entry animation only plays during the intro; later zooms fade tiles in.

## Recording the tour

Real-time screen capture stuttered (software WebGL cannot hold 30 fps), so the clip is rendered offline:
`scripts/rec/capture.mjs` uses timecut to step a virtual clock one frame at a time in headless Chrome,
drives CSS animations by hand each frame, logs when bubbles appear, and hands the frames to ffmpeg at 60 fps.
`scripts/rec/music.mjs` synthesises a light lo-fi bed (no samples) with iMessage-style pops on each bubble
and a chime when the tour starts, synced from that event log. Then the two are muxed.

```bash
cd ~/Desktop/BITS_GOA_2026-27/OOPS/backdoor-blr-map && (python3 -m http.server 8790 --bind 127.0.0.1 >/dev/null 2>&1 &) && cd scripts/rec && npm i timecut --no-audit --no-fund && node capture.mjs video 60 38.5 "$PWD/tour60.mp4" 6.8 && node music.mjs tour60.events.json music.wav && ffmpeg -y -i tour60.mp4 -i music.wav -filter:a "volume=0.5" -c:v copy -c:a aac -b:a 160k -shortest ../../video/backdoor-bengaluru-tour.mp4
```

The last argument of capture.mjs is the virtual second at which the tour starts. It uses the installed
Google Chrome (`executablePath` in the script) with SwiftShader, so it runs without a GPU.

## Office verification

`data/offices.json` is a hand-checked table, one entry per company: `presence` (verified | unverified |
remote | planned), the address when a reliable source gives one, the source URL, and a note. Sources are the
company's own contact/office pages where they exist, otherwise press reports of leases and openings, and
company directories (PitchBook, CB Insights, Clay, Built In) as a last resort. `scripts/geocode-offices.mjs`
turns addresses into coordinates by landmark; `keepOsm: true` keeps the OpenStreetMap office entry when the
research corroborated it; `drop: true` removes a company (GitHub: no current Bengaluru roles or office found).
Build order: offices.json overrides the geocoder. On the page, a company whose office exists but whose address
is not published, or whose office could not be confirmed, gets a dashed pin, a "location approx." label and a
yellow note on its card saying what is and is not known, with the source linked. A pin is never placed at a
specific building unless the address came from a source.

## iMessage panel

The left column copies Backdoor's own iOS 26 iMessage kit (glass header with back/unread, avatar and name pill,
FaceTime button; blue-gradient outgoing and grey incoming bubbles with real tails; "Delivered" → "Read"; typing dots;
the glass "+" and "iMessage" compose row). There is no text input on the page: the compose row, the "+" and every
"Get me in" open Messages to Backdoor's line with a prefilled text.

## Messaging and analytics

"Get me in" on each card opens https://backdoorai.app (with utm_source=bengaluru-map and the company as utm_content). The compose row, the + and Backdoor's last bubble still open iMessage via `sms:+14154907396?&body=Hey Backdoor, I want to work at <Company> as <Role>.`
(the number comes from the live site's `/api/public-line`). If Messages does not open within ~1.6 s (Android,
in-app browsers, sandboxed frames) a sheet shows the number and the message with copy buttons.
Every meaningful click is tracked through `window.visitors.track` / `window.datafast` (the Backdoor app's globals),
`window.bdTrack` if defined, and `dataLayer` / `plausible` / `gtag` / `posthog` if present; event names are in `HANDOFF.md`.

## Self-hosting

Serve the folder statically. `standalone.html` loads MapLibre from unpkg and Inter + Libertinus Serif
from Google Fonts; everything else is local. The WhatsApp number comes from `lib/channels.ts` in the app repo.
